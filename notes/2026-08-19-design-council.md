## 议题

网页委托工具的顶层设计：什么形态下有价值、接口怎么设计成本最低、内部循环的边界。

## chatgpt 的意见（压轴，多方之最）

核心命题："**网页模型委托的价值不是多一个意见，而是把一段昂贵的认知工作完整外包，
只把高信息密度结果交还外层。**" 设计总原则："**不要优化回答质量，要优化外层最终
需要消费多少 token 才能采取正确动作。**"

1. 值得委托的四类任务：①大量阅读/比较→少量结论（审计/评审/综合）；②第二观察者
   价值（找漏洞/反证/trade-off）；③搜索空间大但验证便宜（定位 bug/候选根因）；
   ④有明确验收标准、外层无需理解全部推理。不划算：简单问答、强依赖外层隐式状态、
   返回内容本身很长。
2. **Decision Packet**：默认回传服务端整理的 {结论 / 关键证据 / 分歧或不确定性 /
   建议动作 / 是否需外层介入 / 原文句柄}——比 glm 三级返回更完整的标准形态；
   附 output_budget、confidence、stop_when_sufficient 参数。
3. continuation handle 定向追问（"只验证第 2 点""展开风险 A"）——与 deepseek/glm
   共识一致，且给出具体形态。
4. 循环两层并存：纯咨询=默认安全层，内部工具循环=**显式升级层**；能力分层白名单
   （网络搜索/只读文件/沙箱执行；写文件限临时区；禁任意 shell、凭据、支付等副作用；
   跨边界动作须外层批准）。

## 两家独立达成的设计共识（未事前沟通）

1. **结果压缩是最高杠杆**——deepseek："前置 Schema 压缩，token 降 80%+"；
   glm："服务端强制结构化输出（结论/置信度/关键依据/分歧点），是已被反复验证的最高杠杆设计"。
   与外层此前判断的 post-execute 缺失完全吻合，且给出了具体形态。
2. **断点续问是消除外层重组成本的关键**——deepseek："sessionId+cursor，中途可断"；
   glm："会话句柄 + followUp(question, ref='answer.section3')，引用小节而非复述原文"。
   网页物理会话连续性已存在，缺的只是句柄 API。
3. **流式应当放弃**——glm："逐 token 读流=成本原样转嫁，正确形态是服务端吸收完毕、压缩后一次返回"。
   （外层同意：当前实现的流式增量只落日志，未暴露给调用方，方向一致。）
4. **内部循环的安全边界=不受信任的顾问**——两家用词不同但边界完全一致：
   只读白名单（deepseek：querySelector/scroll/getBoundingClientRect；glm：web search/fetch/read file）、
   禁一切写操作、步数/token 硬上限（deepseek 提议 ≤5 步）、**工具调用轨迹随结论回传供审计**（glm）。

## 互补洞察（各自独有）

- **deepseek：不可替代价值 = 实时网页状态提取**——"答案依赖目标页面当前 DOM、外层无法静态推导"
  （动态表格字段、按钮可点击性断言）。提示：网页不只是模型入口，还是**浏览器**——
  `web_extract(schema)` 型工具是外层没有的**感知能力**，不是视角。
- **glm：价值三分法**——①被咨询方独有上下文（联网检索/新版本文档/小众 issue）②高代价决策的
  第二意见（分歧本身是信号，仲裁只在此时启用）③长文压短；此外"多一个视角净收益为负，不必挽留"。
- **glm：三级返回**——TL;DR / 详细要点 / 原文引用，外层按需下钻（原文留服务端）。

## 修订案 v2（综合采纳，四方共识）

| # | 改动 | 依据 |
|---|---|---|
| R1 | **Decision Packet 压缩层**：默认回传 {结论/关键证据/分歧/建议动作/是否需介入/原文句柄}，原文落服务端 | chatgpt + 共识 1 |
| R2 | 断点续问：continuation handle + 定向追问（"只验证第2点"），物理会话已有，补 API | 三方一致 |
| R3 | 砍流式暴露（维持现状：流式仅用于服务端内部观察） | 共识 3 |
| R4 | 新增提取型工具 web_extract(schema)：网页的浏览器属性变现 | deepseek 独有 |
| R5 | 多路仲裁模式化：仅高不确定高价值场景，服务端汇总"共识+分歧"，不拼全文 | chatgpt + glm 三分法 |
| R6 | M4 重定义为**显式升级层**：默认纯咨询，循环需显式请求；只读白名单+能力分层+步数上限+轨迹随结论回传 | 共识 4 + chatgpt 分层 |
| R7 | 设计总原则入宪法：**优化"外层消费多少 token 才能采取正确动作"，不优化"回答质量"** | chatgpt 金句 |

## 元观察

本次会议本身就是"高代价决策第二意见"场景（glm 三分法之②）的正面示例：
两家独立共识直接构成了修订案的骨架，净收益为正。外层成本控制的关键改进（R1）
恰好也是两家共识的第一条。
