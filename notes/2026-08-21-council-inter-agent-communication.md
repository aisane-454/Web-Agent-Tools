# 2026-08-21 设计会：网页 agent 间通信的丰富程度（三路并行，78s）

议题：服务端编排的网页间通信（不经外层）值得丰富到什么程度。
出席：deepseek(9s/507字) chatgpt(26s/1333字) glm(78s/1053字)，并行。

## 四候选表决
| 候选 | deepseek | chatgpt | glm |
|---|---|---|---|
| 生成-审查-修订闭环 | 不值得 | 值得（轮≤2+hash溯源） | 值得（轮≤2+packet压缩意见） |
| 并行议事会 | 改造后值得 | 改造后值得（加 synthesis 步） | 改造后值得（opt-in+共识摘要） |
| 辩论模式 | 不值得 | 不值得（最后发言者偏置） | 不值得（谄媚从众/共识坍塌） |
| 交叉验证 | 值得（纯机械diff） | 改造后值得（语义归一后再比） | 改造后值得（结构化diff） |

辩论模式三家全票否决。

## 最大收敛：两家独立提出同一原语
chatgpt"条件升级式流水线" ≡ glm"质量信号触发的条件升级链"：
把现有修复兜底**泛化为声明式升级状态机**——机械校验过→直接返回；
失败/可疑→按声明式升级表触发（格式坏→跨模型修复；语义可疑→审查→修订；
高风险→交叉验证）；链长硬上限；每步物理发送带 purpose+artifact hash 可审计。
修复兜底是这个原语的第一个已验证特例（16.7s 实测）。
deepseek 补充最严立场：服务端只许纯机械比对/拼接，禁止择优/融合/改写——
任何"聪明合并"都是不可审计的中间推理。

## 两记警钟（互补）
- chatgpt：服务端悄悄变成第二个 orchestrator——必须声明式有限状态机算子
  （固定角色/轮数/schema/升级条件），保住"外层决策、网页有界执行"边界。
- glm：闭环回声——错误被逐轮强化、失败被编排层隐藏。对策：升级链触发本身
  视为可疑信号写进溯源，连续触发升级的 executor 降权。

## 建议实施序（外层综合三家）
1. 声明式升级链框架（把修复兜底重构成表驱动，零行为变化打底）
2. 生成-审查-修订闭环作为链上第二个算子（review_round 参数，≤2 轮）
3. 结构化交叉验证（代码 token-diff，分歧段带双方节选）
4. 议会 synthesis 步（共识/分歧/建议/少数意见 四字段）
辩论模式不建。

## 用户裁定 + 缺口闭合（会后，同日）

用户反驳三家的审计类担忧："记录都在本地，只是不直接推给外层；外层存疑可
随时读取本地记录" —— **pull 式审计取代 push 式透传**。"不进外层上下文"
是 token 决策，不是信息隐藏决策。裁定成立。

但核查发现原日志只存指纹和字符数，全文未落盘——pull 无物可拉。已闭合：
- turnLog 新增 storeArtifact：answer / deliverable / repair-input /
  repair-output / salvage 五类全文快照到 logs/artifacts/<日期>/，
  索引事件 artifact.stored（hash + 路径）进 turns.jsonl。
- 实测：ask → 快照落盘 + 索引可查（0600 权限）。

据此设计的更新：
- 审计类担忧全部消解（中间产物随要随取，含修复双输入、议会全文）。
- deepseek"禁止聪明合并"的红线放宽为：任何合并/综合步骤必须是一次
  有日志的显式网页调用或确定性代码——即"可拉取"替代"禁止"。
- 仍然成立的护栏只剩两条工程约束：轮次有界（成本）、产物无损（红线）。
- glm 的"闭环回声"从"失败被隐藏"降级为"失败可事后定位"（质量风险
  仍在，但可调试性完全不同）。
